# Skill: sync-upstream — プロジェクト改善をマスターに反映

このプロジェクトで生まれた汎用的な改善を `claude-config-master` へ PR として反映する。

## トリガー

「マスターに改善を反映して」「この改善を上流へ同期して」と言われたとき

---

## 前提: マスターパスの設定

```bash
# 一度だけ設定する（全プロジェクト共通）
echo "/absolute/path/to/claude-config-master" > ~/.claude/master-path
```

設定済みか確認:
```bash
cat ~/.claude/master-path
```

---

## 手順

### 1. マスターパスを確認する

```bash
MASTER=$(cat ~/.claude/master-path 2>/dev/null || echo "")
if [[ -z "$MASTER" || ! -d "$MASTER" ]]; then
  echo "ERROR: ~/.claude/master-path が未設定または無効です"
  echo "設定方法: echo \"/path/to/claude-config-master\" > ~/.claude/master-path"
  exit 1
fi
echo "Master: $MASTER"
```

### 2. 差分を洗い出す

```bash
MASTER=$(cat ~/.claude/master-path)

for dir in agents hooks rules skills; do
  echo "=== .claude/$dir vs $MASTER/$dir ==="
  diff -rq ".claude/$dir/" "$MASTER/$dir/" 2>/dev/null || true
done
```

### 3. 汎用性を判断する

差分ファイルごとに次の基準で分類する:

| 条件 | 判断 |
|------|------|
| CLAUDE.md / ARCHITECTURE.md / PROJECT_STATUS.md | **スキップ**（プロジェクト固有）|
| プロジェクト名・DB名・サービス名を含む | **スキップ** |
| エージェント手順の汎用的改善（特定アプリに依存しない）| 候補 |
| フックの検出精度向上・バグ修正 | 候補 |
| ルール・スキルの追加・改善 | 候補 |

**候補ファイルの一覧を人間に提示して確認を求める。承認後にのみ次へ進む。**

### 4. マスターに反映する

```bash
MASTER=$(cat ~/.claude/master-path)
PROJECT=$(basename "$(pwd)")
BRANCH="improve/from-${PROJECT}-$(date +%Y%m%d)"

cd "$MASTER"
git checkout main && git pull
git checkout -b "$BRANCH"

# 承認されたファイルをコピー
# cp "元ファイルパス" "$MASTER/対応パス"

git add -A
git commit -m "$(cat <<EOF
improve: [改善内容の概要]

Synced from $PROJECT

Co-Authored-By: sync-upstream-skill <noreply@anthropic.com>
EOF
)"

gh pr create \
  --title "improve: [改善内容の概要]" \
  --body "$(cat <<EOF
## 改善内容

[説明]

## 反映元

Project: $PROJECT
Date: $(date +%Y-%m-%d)

🤖 Generated by sync-upstream skill
EOF
)"
```

---

## 注意事項

- PR 作成後は必ず人間がレビューして master にマージすること
- マスターへのマージ後は他プロジェクトへの下流同期（sync-downstream）を検討する
