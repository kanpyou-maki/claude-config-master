# 摩擦ログ (Friction Log)

エージェントが作業中に遭遇した「繰り返す摩擦」を記録するファイル。
ハーネス自己改善ループの**入力**であり、`improve-harness` スキルがこのログを消費して
`.claude/` 配下の設定（agents / hooks / rules / skills）の改善に変換する。

## 記録ルール

- **記録するもの:** 同種の問題が 2回以上起きたとき、review-loop で同一ステージの BLOCK が 3回続いたとき、ツール・ドキュメント・ガードレールの不足で手戻りが生じたとき
- **記録しないもの:** 一度きりの実装ミス（それは通常の修正で終わり）
- 各エントリは「何が起きたか」ではなく「**なぜ繰り返すのか**」まで書くこと
- `improve-harness` で解消したエントリは Status を `resolved` にし、対応した変更（PR・コミット）を記録すること

## エントリ形式

```markdown
### FRIC-NNN: <短いタイトル>

- **日付:** YYYY-MM-DD
- **状況:** 何をしていて、何に繰り返しつまずいたか
- **根本原因の仮説:** ツール不足 / ガードレール不足 / ドキュメント不足 / エージェント指示の曖昧さ
- **改善候補:** どのファイル（.claude/agents|hooks|rules|skills、docs/）をどう変えるか
- **Status:** open | resolved (<PR/コミット>)
```

---

## エントリ

番号はこのリポジトリ内の通し番号。配布先プロジェクトの摩擦ログの番号（sync-upstream の PR が引用するもの）とは別。

### FRIC-001: フックが違反を検出してもモデルに届かず、サブディレクトリでは起動もしない

- **日付:** 2026-10-06
- **状況:** 配布先（vid-cut）の履歴で、フック実行のおよそ半分が `Cannot find module` で失敗し、成功した実行も違反をモデルに渡していなかった。同じ種類の指摘（リンク切れ・古い記述）がレビューのたびに再発していた
- **根本原因の仮説:** ガードレール不足。フックの入出力の約束（終了コードと出力先）がどこにも書かれておらず、テストもフックを関数として呼ぶだけで、プロセスとしての挙動を検証していなかった
- **改善候補:** `.claude/hooks/` の 4 本を終了コード 2 / `additionalContext` に揃える。`settings.json` を `$CLAUDE_PROJECT_DIR` 起点にし、相対パスを ARCH-004 違反にする。`test/hook-contract.test.js` で固定する
- **Status:** resolved (PR #7、ADR-005)

### FRIC-002: スキルの使いどころがスキル一覧に出ず、呼び出されない

- **日付:** 2026-10-06
- **状況:** スキル 5 本に frontmatter がなく、一覧には見出しだけが出ていた。`improve-harness` は配布先で一度も呼び出されていなかった
- **根本原因の仮説:** ガードレール不足。SKILL.md の形式を検査するものがなかった
- **改善候補:** 5 本に name / description を付け、`structure-test.js` で description の欠落を違反にする
- **Status:** resolved (PR #7)

### FRIC-003: quality-gate が、整形ツールを決めていないプロジェクトを Prettier の既定値で整形する

- **日付:** 2026-10-06
- **状況:** master で Write したテストファイルが、既存のスタイル（シングルクォート）と違う形に整形し直され、書き直しになった。以後はフックを通らない方法で編集する必要があった
- **根本原因の仮説:** ガードレールの既定値がプロジェクトの選択を上書きしていた。Biome の設定がなければ無条件に `npx prettier --write` を実行していた
- **改善候補:** `.claude/hooks/quality-gate.js` は、Prettier の設定があるときだけ Prettier を実行する。Biome も Prettier も設定がなければ整形しない
- **Status:** resolved (PR #7)

### FRIC-004: master の摩擦ログが配布物の雛形を兼ねていて、master 自身の摩擦を書けない

- **日付:** 2026-10-06
- **状況:** `docs/friction-log.md` は新規インストール時にそのままコピーされるため、master にエントリを書くと配布先に混ざる。結果として master の摩擦ログは空のままで、自己改善ループの入力がなかった
- **根本原因の仮説:** 配布定義の不足。「master と同じ内容で配る docs」と「プロジェクトごとに中身が育つ docs」を区別していなかった
- **改善候補:** 雛形を `templates/docs/friction-log.md` に分け、`dist-manifest.json` の `docsTemplates` から配布する
- **Status:** resolved (PR #7)

### FRIC-005: 状態ファイルが、状態ではないもので肥大化する

- **日付:** 2026-10-07
- **状況:** 配布先（vid-cut）の `PROJECT_STATUS.md` が 4 日で 95KB になった。93% は「決定事項」と「メモ」で、いまの状態は 1.5% だった。毎セッションの最初に全文を読み、節どうしの食い違いをレビューで繰り返し指摘されていた
- **根本原因の仮説:** ガードレール不足。必ず読まれて上限のないファイルは、確実に伝えたいことの書き場所として最も手軽になる。テンプレートに「完了済み」「決定事項」「メモ」の節があり、埋めるよう促していた
- **改善候補:** テンプレートを 4 節に絞る。`.claude/hooks/arch-lint.js` に ARCH-007（6KB 以内）を足す。更新の時機を「PR の前とセッションを閉じる前」にし、review-loop と self-reviewer に入れる
- **Status:** resolved (ADR-006)

### FRIC-006: ARCH 規則を足すたびに、番号の範囲を十数か所で直す

- **日付:** 2026-10-07
- **状況:** 「ARCH-001〜006」のような範囲が、CLAUDE.md・README・エージェント定義など十数か所に書かれていた。ARCH-006 を足したときは arch-reviewer と設計書に「〜005」が残り、ARCH-007 を足すときも同じ直しが要った
- **根本原因の仮説:** ドキュメントの重複。規則の一覧が ARCHITECTURE.md と `arch-lint.js` にあるのに、範囲だけを各所に写していた
- **改善候補:** 一覧以外の場所では範囲を書かず「ARCH-NNN」とする
- **Status:** resolved (ADR-006 と同じ PR)
