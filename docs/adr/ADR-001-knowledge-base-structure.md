# ADR-001: 知識ベース構造 — CLAUDE.md を地図として簡素化し docs/ に知識を分散する

**ステータス:** 承認済み  
**作成日:** 2026-06-05  
**決定者:** プロジェクトオーナー

---

## Context（背景）

現在の `CLAUDE.md` はエージェントへの指示・開発ルール・エージェント一覧・コーディング原則・ドキュメントテンプレートのすべてを1ファイルに集約している。その結果、以下の問題が生じている。

1. **コンテキストウィンドウの過剰消費**: エージェントが毎回 `CLAUDE.md` 全体を読み込むため、有効なコンテキスト容量が圧迫される
2. **指示の見落とし**: ファイルが肥大化するにつれ、エージェントが後半の重要な指示を見落とすリスクが高まる
3. **単一障害点**: 一箇所への集約は変更競合や肥大化の加速を招く
4. **検索性の低下**: エージェントが特定の情報を参照したい場合、ファイル全体を走査する必要がある

ハーネスエンジニアリングの知見によれば、`AGENTS.md`（本リポジトリの `CLAUDE.md` に相当）は「百科事典」ではなく「地図（目次）」として機能すべきであり、深い情報は `docs/` 配下の個別ファイルに委譲する設計が有効とされている。

---

## Decision（決定）

`CLAUDE.md` を **≤100行の地図ファイル** に簡素化し、詳細な知識を `docs/` 配下の構造化されたファイル群に分散する。

### 具体的な変更内容

**CLAUDE.md に残す情報（地図）:**
- リポジトリの目的（3行以内）
- 重要ファイルへのリンク集（ARCHITECTURE.md, docs/design.md 等）
- クイックスタート手順
- エージェント一覧（名前・役割・起動トリガーのみ）
- 開発フローの概要（フェーズ名と参照先のみ）

**docs/ に移動する情報:**

| 現在の記述箇所 | 移動先 |
|----------------|--------|
| 開発フローの詳細説明 | `docs/design.md` |
| コーディング原則 | `rules/common/coding-principles.md` |
| ドキュメントテンプレート | `docs/references/doc-templates.md` |
| エージェント詳細説明 | 各 `agents/*.md` |
| アーキテクチャ構造 | `ARCHITECTURE.md` |

---

## Consequences（結果）

### ポジティブ

- エージェントが `CLAUDE.md` を読み込む際のコンテキスト消費を大幅に削減できる
- 各ファイルが単一責任を持つため、メンテナンスが局所化される
- エージェントが「どこに何が書かれているか」を CLAUDE.md 一枚で把握でき、必要な情報に直接ナビゲートできる
- 複数人・複数セッションによる並行作業時の変更競合が減少する
- 将来的に情報を追加する際も CLAUDE.md が肥大化しない

### ネガティブ

- 移行作業として既存 `CLAUDE.md` の内容を整理・分散する一時的なコストが発生する
- エージェントが詳細情報を得るために追加のファイル読み込みが必要になる場合がある
- ファイル数の増加により、新規貢献者がどこに何があるか把握するまでのオンボーディングコストが若干増す

---

## Alternatives Considered（検討した代替案）

### 案 A: CLAUDE.md をセクションで分割し include する

`CLAUDE.md` の中から他ファイルを `include` する仕組みを設ける案。Claude Code の現仕様では include ディレクティブが動的には機能しないため、採用しない。

### 案 B: CLAUDE.md を複数ファイルに分割せず整理のみ行う

`CLAUDE.md` を 200行程度に抑えつつ、現状の単一ファイル構成を維持する案。コンテキスト消費と単一障害点の問題が解消されないため、採用しない。

### 案 C: プロジェクトごとに異なる CLAUDE.md を install.sh で生成する

target project ごとにカスタマイズされた `CLAUDE.md` を生成する案。テンプレートリポジトリ自身の知識管理問題が解決されないため、今フェーズでは採用しない（将来の Phase 5 で検討）。
