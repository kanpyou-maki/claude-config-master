# PRD: claude-config-master へのハーネスエンジニアリング導入

**ステータス:** 承認済み  
**作成日:** 2026-06-05  
**対象リポジトリ:** claude-config-master

---

## 1. 問題定義

### 背景

claude-config-master は Claude Code 設定テンプレートの配布リポジトリとして機能している。現状、エージェントへの指示・ルール・スキルが単一の `CLAUDE.md` に集約されており、以下の課題が顕在化している。

### 課題

| # | 課題 | 影響 |
|---|------|------|
| 1 | `CLAUDE.md` の肥大化 | コンテキストウィンドウを過剰消費し、エージェントが重要な指示を見落とす |
| 2 | 知識の非構造化 | アーキテクチャ上のルールが散在し、エージェントが自己参照できない |
| 3 | アーキテクチャ規則の手動管理 | ドキュメント記述のみでは逸脱を検出・阻止できない |
| 4 | 実行プランの管理不在 | タスク計画が一時的な会話に存在し、セッション横断で追跡できない |
| 5 | フィードバックループの欠如 | 品質劣化を自律的に検知・修正する仕組みがない |

### ゴール

エージェントが「リポジトリ自体から推論できる」構造を実現する。ドキュメント・コード・設定が整合した状態を機械的に保証し、Claude Code エージェントの自律性と再現性を高める。

---

## 2. ユーザーストーリー

### エンジニア（テンプレート利用者）として

- **US-01**: プロジェクトに install.sh を実行するだけで、ハーネスエンジニアリング済みの設定一式が展開されてほしい
- **US-02**: アーキテクチャ規則への違反がコミット前に自動検出され、修復手順が提示されてほしい
- **US-03**: 実行中のタスク計画がリポジトリ内に記録され、セッションをまたいで状態を回復できてほしい

### Claude Code エージェントとして

- **US-04**: `CLAUDE.md`（地図）を読むだけで、詳細情報の所在を把握できてほしい
- **US-05**: `ARCHITECTURE.md` を参照することで、依存方向とパッケージ構造を即座に理解できてほしい
- **US-06**: 品質スコアとギャップ情報を `QUALITY_SCORE.md` から取得し、次に優先すべき改善箇所を判断できてほしい
- **US-07**: GC エージェントが定期的に黄金原則への逸脱を検知し、リファクタリング PR を自動作成してほしい

### テンプレートメンテナーとして

- **US-08**: 構造テストがリポジトリの整合性を継続的に検証し、手動レビューの負担を減らしてほしい
- **US-09**: ADR によってアーキテクチャ上の決定とその根拠が永続的に記録されてほしい

## 3. 成功指標

| 指標 | 現状 | 目標 |
|------|------|------|
| `CLAUDE.md` の行数 | >200行（肥大化） | ≤100行（地図として機能） |
| アーキテクチャ違反の自動検出率 | 0%（手動のみ） | 100%（リンターフックで全検出） |
| 実行プランのセッション横断追跡 | 不可 | `docs/exec-plans/` で完全追跡 |
| テストカバレッジ（hooks/） | 未計測 | ≥80% |
| GC エージェントによる自律修正 | 未実装 | 週次実行・PR 自動作成 |
| install.sh による展開所要時間 | 手動確認が必要 | 5分以内・無人実行 |

---

## 4. スコープ外

- **他ツールチェーンのサポート**: GitHub Actions・GitLab CI への自動連携（将来検討）
- **マルチリポジトリ管理**: 複数の target project を一元管理するダッシュボード
- **GUI/Web UI**: 設定管理画面の提供
- **モデル固有の最適化**: 特定の Claude モデルバージョンへの依存した最適化
- **既存 target project の自動移行**: すでに install.sh を適用済みのプロジェクトへの自動アップグレード
